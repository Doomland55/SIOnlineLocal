# Локальный сервер SIGame («Своя игра»)

Мини-сервер на Node.js, который поднимает полноценную игру в локальной сети
(или на одном компьютере): игроки открывают в браузере `http://<IP>:<порт>/`
и играют в «Свою игру» без внешних сервисов и без интернета.

Сервер написан **без npm-зависимостей** — используются только встроенные модули
Node.js (`http`, `crypto`, `zlib`, `fs`). Всё, что нужно, — установленный Node.js 18+.

## Что умеет

- отдаёт собранный веб-клиент (тот самый интерфейс SIOnline) с того же адреса,
  что и API, поэтому нет проблем с CORS и смешанным содержимым;
- принимает пакеты вопросов `.siq` прямо из браузера, распаковывает их и
  показывает темы, вопросы, ответы, комментарии;
- раздаёт медиафайлы пакета по `http://<IP>:<порт>/media/<hash>/<файл>`
  с поддержкой `Range` (перемотка аудио/видео) и `ETag`;
- синхронизирует игру через SignalR-хабы `/sionline` (лобби) и `/sihost` (игра)
  в формате MessagePack — тем же протоколом, что и настоящий SIGame-сервер;
- ждёт загрузки мультимедиа всеми игроками перед началом вопроса;
- отдаёт права ведущего создателю игры (`HOSTNAME`): он может начать игру,
  пропустить вопрос или раунд (`MOVE`) и вручную поправить счёт игрока
  (`CHANGE` → `PLAYER_SCORE_CHANGED` + `SUMS`), а игроки могут «пасовать» (`PASS`);
- находит медиафайлы пакета, даже если имя в `content.xml` отличается регистром,
  содержит обратные слэши или другие пробелы/кириллицу;
- поддерживает чат, PIN-коды игр, аватары, статистику и историю в рамках клиента.

## Быстрый старт

```bash
npm install          # один раз, нужен только для сборки клиента
npm run build-prod   # собирает веб-клиент в dist/ (~1 минута)
npm run server       # запускает сервер на порту 8080
```

После запуска в консоли появятся адреса:

```
  На этом компьютере:  http://localhost:8080/
  В локальной сети:    http://192.168.1.42:8080/  (Wi-Fi)
```

Игроки вводят адрес из строки «В локальной сети» в браузере (телефон, ноутбук,
планшет — любое устройство в той же сети). Создатель игры загружает `.siq`
через интерфейс, остальные подключаются к созданной игре по PIN-коду или
через список игр в лобби.

### Опции командной строки

```
node server/cli.js [опции]

  --port, -p <число>   Порт (по умолчанию 8080)
  --host <адрес>       Интерфейс прослушивания (по умолчанию 0.0.0.0 — вся сеть)
  --client <путь>      Каталог с собранным клиентом (по умолчанию dist)
  --data <путь>        Каталог данных (по умолчанию server/data)
  --open               Открыть браузер после запуска
  -h, --help           Справка
```

Пример: `node server/cli.js --port 3000 --open`

### Если игроки не подключаются

1. **Брандмауэр.** Разрешите входящие соединения на выбранный порт
   (Windows: «Брандмауэр Защитника Windows» → «Разрешённые приложения»;
   Linux: `sudo ufw allow 8080/tcp`).
2. **Один адрес.** Клиент и API работают на одном порту — открывать нужно ровно
   `http://<IP>:<порт>/`, без `https` и без прокси.
3. **Та же сеть.** Телефон и компьютер должны быть в одной подсети; гостевые
   Wi-Fi сети часто изолируют клиентов друг от друга.
4. **IP-адрес.** В консоли выводятся все сетевые интерфейсы — выберите тот,
   который относится к нужной сети (Wi-Fi/Ethernet).

## Как устроена синхронизация вопросов и медиа

1. Создатель игры загружает `.siq` (`POST /api/v1/content/packages`). Сервер
   считает SHA-1 архива, распаковывает его в `server/data/packages/<hash>/`
   и запоминает содержимое (`content.xml` + файлы пакета).
2. Клиенты получают описание раунда и вопросов через `/sihost` — текстом,
   с экранированием переводов строк. Медиафайлы в описании заменяются на
   `<SERVERHOST>/media/<hash>/<путь>/<файл>`, поэтому каждый игрок загружает их
   со своего адреса сервера (важно при игре по LAN-IP). Если файла в архиве нет,
   клиенту вообще не отправляется ссылка — иначе картинка «висит» со спиннером
   и игра ждёт `MEDIALOADED`, которого не будет.
3. Когда вопрос выбран, сервер отправляет контент и **ждёт подтверждения
   `MEDIALOADED` от всех игроков** (или истечения таймаута). Только после
   этого начинается фаза нажатия (`Press phase started` в логе), поэтому у всех
   участников картинка/звук/видео уже загружены.
4. Файлы отдаются с `Content-Length`, `Content-Range` и `ETag`: браузер может
   кэшировать и перематывать их, а повторные вопросы открываются мгновенно.
5. Ход игры (`INFO2`, `TABLE`, `THEME`, `QUESTION`, `ANSWER`, `ISRIGHT`,
   `PERSON`, `SUMS`, `TIMER`, …) рассылается сервером всем участникам и
   досылается опоздавшим игрокам в виде снапшота.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/si/servers` | Список серверов (для автообнаружения) |
| `GET /api/v1/info/host` | Информация о сервере: имя, лицензия, `contentInfos`, лимит размера пакета |
| `GET /api/v1/info/bots` | Компьютерные игроки (здесь отсутствуют) |
| `GET /api/v1/info/storage-filter/:id` | Хранилища пакетов (здесь отсутствуют) |
| `POST /api/v1/games` | Создать игру из загруженного пакета |
| `GET /api/v1/games?pin=<pin>` | Найти игру по PIN |
| `* /api/v1/content/...` | SIContent-совместимый сервис: загрузка/поиск/выдача файлов |
| `GET /media/<hash>/<файл>` | Медиафайлы пакета (Range, ETag) |
| `WS /sionline` | SignalR-хаб лобби: список игр, создание, удаление |
| `WS /sihost` | SignalR-хаб игры: подключение к комнате и игровые сообщения |

Адрес сервера во всех ответах берётся из заголовка `Host` (или
`X-Forwarded-Host`/`X-Forwarded-Proto` при работе за обратным прокси), поэтому
ссылки на медиа всегда указывают на тот адрес, по которому пришёл игрок.

## Данные

```
server/data/
  packages/<sha1>/        распакованные пакеты вопросов
  avatars/<sha1>/         загруженные аватары
```

Каталог можно изменить опцией `--data`. Удаление каталога сбрасывает все
загруженные пакеты.

## Настройка клиента

Клиент, отданный сервером, автоматически определяет, что API находится на том
же адресе (`GET /api/v1/info/host` → JSON), и подключается к нему вместо
публичного списка серверов. Дополнительная настройка не требуется.

Если клиент и сервер всё же разнесены по разным адресам (например, разработка
через `npm run start`), укажите сервер в `assets/config.js`:

```js
serverUri: 'http://192.168.1.42:8080',
serverDiscoveryUri: '',
```

## Тесты и диагностика

```bash
npm run test:server    # e2e-тест сервера: загрузка пакета, медиа с Range,
                       # подключение игроков, вопрос, ответ, очки, чат

RUN_LOCAL_SERVER_TEST=1 npx jest test/LocalServer.test.ts --runInBand
                       # тот же сценарий, но через настоящий клиентский код
                       # (Redux + GameClient + SIContentClient)

VERBOSE=1 npm run test:server                 # подробный лог шагов
SIGAME_DEBUG_HTTP=1 npm run server            # логировать все HTTP-запросы
SIGAME_DEBUG_WS=1 npm run server              # трассировка WebSocket-кадров
LOCAL_SERVER_TEST_VERBOSE=1 ... jest ...      # состояние клиента в тесте
```

Логи игрового движка подсказывают фазу вопроса:

```
Waiting for media on 2 client(s)   → сервер ждёт мультимедиа
Media loaded by Аня, 1 left        → подтверждения от игроков
Media wait finished                → все готовы, вопрос начинается
Press phase started                → можно нажимать кнопку
```

## Структура

```
server/
  cli.js              запуск из командной строки
  src/
    server.js         HTTP-маршруты, реестр игр, SignalR-хабы
    game.js           движок игры: раунды, вопросы, ответы, очки, таймеры
    package.js        разбор .siq/.siq-архивов и content.xml
    content.js        SIContent-совместимый сервис загрузки и выдачи файлов
    signalr.js        SignalR (MessagePack) поверх собственного WebSocket
    websocket.js      минимальная реализация RFC 6455 без зависимостей
    msgpack.js        кодирование/декодирование MessagePack
    zip.js            распаковка zip (только необходимые методы)
    xml.js            минимальный XML-парсер для content.xml
  test/smoke.js       e2e-тест протокола
```

## Ограничения

- нет авторизации и разграничения прав: сервер рассчитан на доверенную
  локальную сеть;
- максимальный размер пакета — 256 МБ (меняется в `server.js`);
- одновременная работа нескольких игр поддерживается, но сервер не рассчитан
  на сотни подключений — это «домашний» вариант для 2–20 игроков.
