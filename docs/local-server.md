# Локальный сервер SIGame (браузерные клиенты по IP)

В репозиторий добавлен собственный сервер на Node.js/TypeScript, который реализует тот же протокол,
что и центральные серверы SIGame. Благодаря этому обычный веб-клиент из `src/` подключается к нему
**из браузера по IP-адресу** — без установки десктопного приложения и без серверов vladimirkhil.com.

* Игровые хабы SignalR (MessagePack): `sihost` (комнаты и игровой процесс) и `sionline` (лобби).
* REST API: сведения о сервере, создание игры, вход по PIN.
* Раздача `.siq`-пакетов и всех медиафайлов (картинки, аудио, видео, HTML) с этого же сервера.
* Игровой движок: раунды, темы, выбор вопроса, кнопки, ответы, ставки, финальный раунд, таймеры, боты.

## Быстрый старт

```bash
npm install               # один раз
npm run make-test-package # (необязательно) создаёт server/packages/test-package.siq
npm run serve-local       # сборка веб-клиента + запуск сервера
```

Сервер напечатает адреса, например:

```
Локальный сервер SIGame запущен: http://192.168.1.10:8080
Откройте http://192.168.1.10:8080 в браузере, чтобы играть.
```

Ведущий и игроки открывают этот адрес в браузере (в том числе с телефонов в той же сети).
Игра создаётся автоматически для каждого пакета из `server/packages`, плюс можно создать новую
игру из веб-клиента (кнопка создания игры) или нажать «играть одному» — сервер сам добавит ботов.

Если веб-клиент уже собран (`npm run build-local`), достаточно `npm run server`.

## Сборка клиента, «зашитая» на локальный сервер

`npm run build-local` собирает клиент с `assets/config.local.js`:

* `serverUri = window.location.origin` — клиент всегда обращается к тому серверу, с которого загружен
  (localhost, IP в локальной сети, домен, preview-адрес — всё работает одинаково);
* отключены центральные сервисы (discovery, статистика, реестр приложений), поэтому клиент
  не «висит» на недоступных запросах.

Обычная сборка `npm run build-dev` / `build-prod` не меняется и по-прежнему использует
`assets/config.js` с центральным discovery.

## Пакеты и медиа

* `server/packages/*.siq` — локальная библиотека. Пакеты предлагаются клиенту при создании игры
  (`/api/v1/packages`); игры из них создаются по запросу клиента, а не автоматически.
  Автосоздание игр для всех пакетов включает параметр `startupGames: true` в `server/config.json`.
* Загрузка из браузера (создание игры из файла) сохраняется в `server/data/package/<hash>/<имя>.siq`.
* Медиафайлы распаковываются в `server/data/media/<packageId>/{Images,Audio,Video,Html}` и раздаются по
  `/package/<packageId>/<путь внутри пакета>`.
* Синхронизация: клиенты получают:
  * `ROUNDCONTENT` — список медиа раунда для предзагрузки;
  * `CONTENT2` — содержимое вопроса по мере показа (текст, картинка, аудио, видео, HTML);
  * `RIGHTANSWER` и контент ответа;
  * одинаковую длительность показа для всех участников (сервер ведёт тайминг сам).

  Адреса медиа абсолютные и строятся из того адреса, по которому клиент пришёл на сервер, поэтому
  игроки, зашедшие по `localhost` и по IP, видят одни и те же файлы.

## Настройка

`server/config.json` (необязателен) или переменные окружения:

| Параметр | Env | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `port` | `SI_PORT` | `8080` | порт |
| `host` | `SI_HOST` | `0.0.0.0` | интерфейс (0.0.0.0 = доступ из локальной сети) |
| `publicBaseUrl` | `SI_PUBLIC_URL` | автоопределение по IP | адрес, который увидят игроки |
| `name` | — | `SIGame local server` | имя сервера в лобби |
| `packagesDir` | `SI_PACKAGES_DIR` | `server/packages` | библиотека пакетов |
| `dataDir` | `SI_DATA_DIR` | `server/data` | загруженные пакеты, медиа, аватары |
| `clientDir` | `SI_CLIENT_DIR` | `dist` | собранный веб-клиент |
| `maxPackageSizeMb` | — | `512` | максимальный размер пакета |
| `botNames` | — | список имён | имена ботов |
| `timeSettings` | — | значения SIGame | тайминги игры (в секундах) |

Пример `server/config.json`:

```json
{
  "port": 8080,
  "publicBaseUrl": "http://192.168.1.10:8080",
  "name": "Играем дома",
  "botNames": ["Иннокентий", "Александра", "Борис"]
}
```

Если сервер стоит за прокси/туннелем, `publicBaseUrl` можно не задавать: адрес берётся из заголовков
`Host`/`X-Forwarded-Host` того запроса, которым пришёл клиент.

## Проверка

```bash
npm run server     # в одном терминале
npm run test:server  # в другом
```

`test:server` запускает два e2e-скрипта:

* `server/scripts/smoke-test.js` — самописный SignalR-клиент на MessagePack проходит полный цикл:
  REST API → лобби → вход → готовность → старт → раунд → выбор вопроса → показ контента →
  скачивание медиа → нажатие кнопки → ответ → начисление очков → конец вопроса, плюс создание
  автоматической игры.
* `server/scripts/signalr-client-test.js` — проверка **настоящей** библиотекой `@microsoft/signalr`
  (той же, что использует браузер): negotiate, MessagePack-кадры, `TryGetGameInfo`, `JoinGame2`,
  keep-alive, чат, пауза, переход к следующему раунду, PIN и переподключение после обрыва связи.
* `server/scripts/answer-options-test.js` — вопрос с вариантами ответов: раскладка `ANSWER_OPTIONS`,
  показ вариантов A–D, выбор варианта по метке и начисление очков.
* `server/scripts/seats-test.js` — места и роли в лобби: количество столов соответствует настройкам
  создания игры, свободные места видны другим игрокам, вход ведущим и игроком работает,
  занятое место ведущего защищено.
* `server/scripts/host-rights-test.js` — права управляющего: `HOSTNAME` указывает на живого игрока,
  правила игры (`SET_OPTIONS`) принимаются и рассылаются всем, переход к выбранному раунду работает,
  а после выхода игрока остальные получают `DISCONNECTED` и освободившееся место можно занять.

Юнит-тесты движка и загрузчика пакетов: `npm run test:local-server`.

## Места (столы) в игре

* Сервер создаёт ровно столько мест, сколько запрошено: например, «3 игрока» — это три места игроков
  и ещё одно свободное место для того, кто присоединится, а не фиксированные 6 столов.
* Пустые места видны в лобби как offline-персоны с ролью `Player`, поэтому в карточке игры активна
  кнопка «подключиться игроком».
* Место ведущего по умолчанию ведёт сервер: пока его не занял живой игрок, оно отображается свободным
  и вход ведущим доступен. После входа место защищено от других игроков.
* Если все места заняты, а игра ещё не началась, сервер добавит стол новому игроку.

## Права на управление игрой

Управляющий определяется в таком порядке:

1. живой подключённый ведущий (место ведущего занял человек);
2. создатель игры, если он подключён;
3. первый подключённый живой игрок.

Имя управляющего приходит в сообщении `HOSTNAME` и обновляется при каждом входе и выходе участника,
поэтому кнопки «старт», «дальше», смена правил, переход к раунду и пауза доступны тому, чьё имя совпадает
с `HOSTNAME`. Для игр, созданных через REST API, это создатель игры (он заходит ведущим). В автоматических
играх и в играх из локальной библиотеки место ведущего ведёт сервер, поэтому права получает первый
подключившийся живой игрок.

Правила игры (`SET_OPTIONS`: устные ответы, управляемая игра, ложные старты, частичный текст и картинки,
скорость чтения, время блокировки кнопки) применяются сразу, даже если игра уже идёт, сохраняются на сервере
и рассылаются всем участникам как `OPTIONS2`, поэтому их видят и те, кто подключился позже. Имена опций в
`OPTIONS2` — те, что понимает веб-клиент: `TimeForBlockingButton` уходит как `ButtonBlocking`,
`PartialImageTime` — как `PartialImage`, `UseApellations` — как `UseAppellations`.

## Устная игра

При `Oral = true` кнопка нажатия не показывается:

* все живые игроки получают `ORAL_ANSWER` и приглашение `ANSWER\ntext`, боты отвечают сами;
* ответ игрока уходит ведущему на проверку: `PLAYER_ANSWER` всем и `ASK_VALIDATE\n<индекс>\n<ответ>\n+`
  ведущему; ведущий подтверждает ответ сообщением `VALIDATE\n<ответ>\n<+|->\n<коэффициент>`
  (индекс игрока тоже принимается — так приходит `ASK_VALIDATE`);
* если живого ведущего нет, ответ проверяется автоматически, чтобы вопрос не завис;
* таймер `TIMER\n2\nGO\n…\n-1` ограничивает время ответа; по его истечении вопрос закрывается.

## Пас и завершение вопроса

Если все игроки, которые ещё могут отвечать, нажали «пас», вопрос завершается (`TIMER STOP`, `ENDTRY`,
правильный ответ и `QUESTION_END`) — и сразу после паса, и когда время нажатия истекло. Пасы не
переносятся на следующий круг нажатий.

## Таблица раунда

Таблица сохраняет исходную размерность: сыгранный вопрос не удаляет тему, а скрывает его цену
(`-1` в `TABLO2`), поэтому тема остаётся на месте до конца раунда.

## Аватары

Аватар, отправленный клиентом (`AVATAR\nimage\n<uri>`), сервер сохраняет и рассылает остальным участникам
как `AVATAR\n<имя>\nimage\n<uri>`, а новым участникам отдаёт вместе с полным состоянием игры.
Клиент отправляет аватар после входа в комнату и переподключения, поэтому аватары синхронизируются
между всеми клиентами; загрузка файлов доступна по `POST /api/v1/content/avatars`.

## Выход игрока из комнаты

* Когда клиент отключается (выход из комнаты, закрытие вкладки), сервер освобождает его место и рассылает
  остальным `DISCONNECTED` с именем участника, `PLAYER_COUNT`, обновлённые `SUMS` и `READY`, а в комнате
  (до старта игры) ещё и `INFO2`; лобби получает уведомление об изменении состава. Клиенты убирают
  участника с его места, и место снова становится свободным — его может занять другой игрок.
* Очки вышедшего игрока не сохраняются на его месте, но при возврате (перезагрузка страницы, повторный
  вход под тем же именем) сервер вернёт игрока на то же место с прежним счётом, если место ещё свободно.

## Структура

```
server/
  config.json.example     пример конфигурации
  packages/               локальная библиотека .siq
  scripts/                генератор тестового пакета и e2e-проверки (smoke, места, права ведущего, правила в игре)
  src/
    index.ts              точка входа: express, HTTP, WebSocket
    config.ts             конфигурация
    protocol.ts           имена сообщений протокола SIGame
    xml.ts                парсер XML (совместим с src/model/siquester)
    signalr/              кадры MessagePack, HubConnection, HubHost (negotiate + WebSocket)
    api/                  REST API, хранилище пакетов/медиа/аватаров, модели контрактов
    game/                 пакеты, библиотека, лобби, игровой движок
    hubs/                 sihost и sionline
```

## Ограничения

* Длинный polling SignalR не поддерживается: используется WebSocket (его поддерживают все актуальные браузеры).
* Голосовой чат, статистика и реестр приложений недоступны локально (запросы к ним отключены в
  `config.local.js` или отвечают пустыми данными). Аватары работают: они загружаются на локальный сервер
  (`/api/v1/content/avatars`) и рассылаются через игру.
* Сложные типы вопросов (кошки, аукционы со ставками ведущего, апелляции) обрабатываются упрощённо:
  обычные вопросы, вопросы с вариантами ответов, медиа, финальный раунд со ставками.
